02

Ontology

Helps AI find the right answer — and show the evidence for it

Ordinary AI retrieval only asks whether the meaning looks close, so it picks the wrong thing on questions with hard conditions (“5 days, 2 people, NT$30,000 budget”). Ontology organises enterprise knowledge into one clearly defined structure of relationships and rules — the Ontology; on top of semantic matching it adds a condition check — so the answer is more accurate, and it can say why this is the answer.

  • Semantic matching plus Ontology condition checks, for more accurate answers
  • Answers are grounded and explainable — not a black box
  • Multilingual — not tied to any one language

04

Frontier / Local / Hybrid orchestration

Private data is always de-identified before it reaches a cloud model

Finance, healthcare and government care about one thing above all: the data must not leave. All-cloud delivers quality but raises doubts; all-on-premises is safe but ties your hands. Riversoft doesn’t force that choice — the system routes by task difficulty and data sensitivity: the most sensitive work stays on a Local model inside the enterprise, and only complex reasoning goes to a Frontier cloud model, de-identified before it leaves, with the re-identification mapping kept on the customer’s side. The cloud model never sees data that identifies a person.

  • Data is de-identified before it reaches a cloud model; the re-identification mapping stays on the customer’s side
  • Local: sensitive tasks run on in-house models — the data never leaves
  • Frontier: complex reasoning goes to frontier cloud models, with no compromise on quality
  • Hybrid: chosen automatically by task and sensitivity — no manual call needed
  • Components can be deployed in the customer’s own data centre, with strict per-customer data isolation

Technical advantages

The advantages come from one architecture: AI handles the understanding, the reasoning engine does the thinking. It fixes the three worst problems of ordinary AI at once — making things up, burning money, and being hard to trust.

69%

Tokens saved per run

On trip planning, one run uses roughly 69% fewer tokens than a pure-AI approach — about 60% lower cost.

No made-up answers

Every key output is logic-checked against the Ontology — “is this restaurant really allergen-free” is confirmed by formal logic, not by the model’s hunch. Hallucination is blocked at the architecture level.

Far lower cost

The AI is called once, to compile the question into a rule. Verification then runs on ordinary CPU — almost no tokens, done in milliseconds.

Cheaper and faster the more you use it

Verified logic is remembered and reused; a similar question skips the AI call entirely. The longer the system runs, the less it costs and the faster it gets.

Safer against over-reach

Permission is checked before the AI acts. Unauthorised operations are blocked structurally, so it never burns resources retrying its way around a permission error.

No answer beats a wrong one

When the conditions can’t all be met, the system relaxes them in a defined order and offers the closest workable option — instead of inventing one or simply failing.
